## Risks

- **Hidden information (item 4) is the main risk.** It is the only item that sends something new about a hidden zone. It goes to the owner alone, is filtered in the worker (HID-001), and is bookkeeping of what the owner was shown and chose, not Forge's per-viewer answer (HID-002) — owner-approved (Decided 2); F-0103-D2 tests it. Presentation (HID-005): the slide-out must not exist in the other seat's DOM at all.

### CONFLICT -- items 1 and 2 (PHASE-003) -- DECIDED 2026-11-18: option A (owner)

- **Requirement.** Item 1: pointing at a report row (or a picture in the full report) dims everything except "that Island on Bob's side". Item 2: the read-through lights each row's card on the table. The research above says each report's cards "carry ids (`match.ts:445`, 672-695), except cards now hidden from that viewer".
- **Observed reality (SOURCE, RUN).** A report's cards carry the report's own stand-in ids (`action:N:I`), never a card's id: `ActionReports` sends them so (Phase 9 Amendment 12; see the `HiddenIds.java` comment "the way Phase 9 Amendment 12's `action` cards are already sent"), and `scripts/check-hidden-tops.py` enforces it ("a report's cards name a card id" is a failure). On the wire in this build's Lab trace: `{"id": "action:1:0", "to": "top", ...}`.
- **Impact.** The page cannot tell which card on the table a report row means. Matching by name is forbidden (PROTO-001) and ambiguous ("which Island" is the very case); matching by the round's `moves` would be a guess. A pile tile can be found from `to` alone; a card on the table cannot.
- **Options.** (A) The worker adds a link to each report card (e.g. `card: "card:N"`), only while this reader's own board shows that card (HiddenIds already strips the id of a card now hidden from the reader), and `check-hidden-tops.py`'s rule becomes "a report card names only an id this reader's board shows" -- a change to a hidden-information rule, so the owner's call. (B) Items 1 and 2 light only pile tiles (cards that went to a graveyard, exile, a hand or a library), nothing on the table -- less than the approved look. (C) Drop items 1 and 2.
- **Recommendation.** A: the dim and the read-through as approved; the link is never sent for a card the reader cannot see, with a bite test for it (HID-004).
- **Question for the owner.** May each report card carry a link to that card on the table, sent only while that player's own board shows it?
- **Decision (owner, 2026-11-18): A.** Each report card may carry `table`, the card's own id, sent ONLY while that viewer's own snapshot shows the card in a `HiddenIds.BOARD` list (battlefield, hand, otherHands, casting, graveyard, exile, command, libraryTop) -- never the stack, never a card in a hidden zone. Recorded in `docs/architecture/MATCH_STATE_VISIBILITY.md` and `protocol/README.md`.
